## 1. Look-ahead bias (PASS)

- `grep -RIn '\.shift(-\d)'` against `train_scanner_short_v2_ml.py`, `train_scanner_long_v2_ml.py`, `features_v2.py`, and the v2 backtests: zero hits in signal/feature code.
- No `rolling(..., center=True)`, no positive `np.roll`.
- Every feature in `features_v2.py:38-202` uses only current and past bars (returns via `close.shift(period)` backwards, RSI / MACD / BB / ATR all lookback-only, OBV polyfit on 24-bar trailing).
- `features_v2.py:240` uses `close.shift(-horizon)` — that's **label construction** for supervised learning, not a feature. Legitimate.
- Entry timing in the live scanner (`live_scanner_v2.py:738`) matches the backtest (`backtest_short_v2.py:140-149`): both use `close[entry_bar]`. Unlike bigmover, no open/close mismatch.

**This is NOT a bigmover-class leak. The classifier's internals are clean.**

## 2. Walk-forward embargo (FAIL — caveat)

- `train_scanner_short_v2_ml.py:82-84`:
  ```python
  folds = [
      ("Fold 1 (60/20)", 0, int(n * 0.6), int(n * 0.6), int(n * 0.8)),
      ("Fold 2 (80/20)", 0, int(n * 0.8), int(n * 0.8), n),
  ]
  ```
- Zero-bar embargo between train (ends at 80%) and test (starts at 80%). The bigmover classifier had an explicit 1-month embargo; v2 has none.
- Not fatal on its own (data is sorted by `signal_time`, so test rows are chronologically after train rows), but violates the post-bigmover standard in CLAUDE.md. If a signal's label-computation window (e.g., forward-24h return) spans the boundary, there's label leakage across the split.

## 3. Survivorship + universe-time (SEVERE FAIL)

**The decisive finding.** Live and backtest universes differ by construction:

- **Backtest universe** (`backtest_short_v2.py:433`):
  ```python
  symbol_dirs = sorted([d for d in RAW_DIR.iterdir() if d.is_dir()])
  ```
  Loads whatever coins have CSV files at `/data/raw/15m/`. ~100 coins. No `listed_since` filter, no warmup gate, no leveraged-token exclusion.

- **Live universe** (`live_scanner_v2.py:128`):
  ```python
  fetch_all_tickers()  # GET /futures/usdt/tickers
  ```
  Returns **every** USDT perp Gate.io lists today, including leveraged tokens and newly listed coins. No filter.

- **Compare to bigmover** which at `backtest_bigmover_longshort_3y_leakfix.py:67`:
  ```python
  LEVERAGED_TOKEN_RE = r"[35][LS]_USDT$"
  ```

  Explicitly excludes 5L/3L/5S/3S tokens. v2 has no analogous filter.

## 4. Threshold selection (SEVERE P-HACK)

- `train_scanner_short_v2_ml.py:39`:
  ```python
  ML_THRESHOLDS = [0.50, 0.55, 0.60, 0.65, 0.70, 0.75]
  ```
- `train_scanner_short_v2_ml.py:177-210`, `find_best_threshold()`:
  ```python
  combined = pd.concat(all_oos, ignore_index=True)
  for thresh in ML_THRESHOLDS:
      mask = combined["ml_prob"] >= thresh
      m = compute_metrics(combined.loc[mask, "pnl_pct"].values)
      if m["trades"] >= MIN_TRADES_PER_FOLD and m["pf"] > best_pf:
          best_pf = m["pf"]
          best_thresh = thresh
  ```
- 6 threshold candidates swept on the same combined OOS that provides the reported PF. Winner (0.70 at PF 5.05) is the **maximum of 6 trials on one dataset**, not an independent OOT measurement. No Bonferroni correction.
- No `PF_p5` (Monte Carlo 5th-percentile bootstrap) reported for the 0.70 winner. For context, bigmover's ML-grid winner had PF_p5 0.61, which alone would have disqualified it under the robustness gate.
- Honest re-audit at `learn/22042026/v2_ml_audit_2026-04-23.md:40` (line 40 of that audit memo) using a held-out validation set selected threshold 0.75 at PF 6.14 — **higher** than the dredged 0.70 at 5.05, which suggests the dredged winner is actually SUBOPTIMAL as well as inflated. Both numbers still have no bootstrap floor reported.

**The "PF 5.05 → 15% Kelly cap" recommendation in memory `project_v2ml_resizing_finding.md` derives from this contaminated number.** If promoted to real money, position sizing would be calibrated to an edge that isn't real.

## 5. Live vs backtest (DIFFERENT STRATEGY)

| Aspect | v2 Backtest | v2 Live paper | Delta |
|---|---|---|---|
| Exit type | Fixed TP (+5% Variant A, +10% Variant B) + hard SL −5% | **Trailing stop only** (`tp_price = 0`, activate +2%, trail −3% from peak) | Strategies are not the same |
| Entry price | `close[entry_bar]`, exits scanned from `entry_bar+1` | `close[i_last]` at signal time, real order fills next bar | ~5–30 bps drift on alt spikes |

Evidence:
- `paper_executor.py:437-440` writes `tp_price = 0` on open for v2.
- `paper_executor.py:508-524` only checks SL and trail on the close loop.
- `backtest_short_v2.py:46` defines variants with explicit TPs (+5% / +10%).

**The 5/5 winning streak in the screenshot**:
- Not take-profit fills (there is no TP). 
- All exits from trail-stop firing at +5.0% after price hit +2%+ then pulled back 3%.
- Consistent with favorable regime × volatile tokens × stochastic trail logic. **Not evidence of strategy edge.**

## What to fix before re-enabling

In priority order (don't skip any):

1. **Universe filter in the live scanner** — add the `LEVERAGED_TOKEN_RE` exclusion and a `listed_since` check that rejects coins with < N days of price history. Prevents the model from trading OOD instruments.
2. **Train/test/holdout split with explicit embargo** — shorten the holdout window so it never overlaps any threshold-selection window. Mirror the pattern from `train_bigmover_classifier.py` (post-shorten).
3. **Bonferroni correction on threshold sweep** — if 6 thresholds tested, adjusted ship floor is `1.30 × 6 = 7.80` (or pick the winner on a held-back fold, never the final OOT).
4. **Backtest the actual trail-stop exit** — either change the live executor to match the fixed-TP backtest, OR create a new backtest that uses `tp_price = 0` + trail-3%, and treat that as the canonical.
5. **Report PF_p5 alongside PF** — no more headline PF without the bootstrap 5th-percentile. If `PF_p5 < 1.30`, the variant is not robust regardless of point estimate.

## Decision

**Disable all 5 v2 paper-trading accounts.** Re-enable only after the 5 fixes above are done and a re-audit passes all gates on a fresh OOT window.

The 5/5 winning streak is noise from a mis-configured live pipeline on a different strategy than any backtest measured. The longer we leave it running, the more we trick ourselves into trusting it.

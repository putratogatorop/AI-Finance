## Two narrative-momentum families

### Family A — Emergent cohort momentum (data-driven)

For each `(symbol, timestamp)`:
- **Cohort identification:** rolling 30-day Pearson correlation of 4h returns with every other coin in the universe; pick the top-10 most correlated using data **strictly ≤ t**. To save compute we anchor cohort identification at **weekly** boundaries (52/yr × 6 yr = 312 anchors), and reuse the most recent anchor for any timestamp inside its week.
- **Feature:** `cohort_momentum_7d` = mean of (close-to-close 7d return) of the top-10 cohort, computed over the 7 days **ending at t** (still strictly past).

**Captures:** "this coin's tribe is pumping right now." If memes are running and PEPE is in the cohort, cohort_momentum spikes whether or not we ever named "memes."

**No look-ahead:** correlation lookback uses `[t-180bars, t)`, returns measurement uses `[t-42bars, t)`. Both fully past.

**Compute:** ~25 min on Mac with weekly anchors. 200×200 correlation matrix on 30-day window per anchor = 5 sec × 312 anchors.

### Family B — CoinGecko category momentum (semantic)

For each main narrative category (Memes, RWA, AI Tokens, DePIN, GameFi, DeFi, Layer-1, Layer-2, Privacy, Gaming, plus "Solana ecosystem" / "Ethereum ecosystem" if useful):
- **Membership:** fetched from CoinGecko's `/coins/categories` API. Mapped from CoinGecko symbol IDs to our `<TICKER>USDT` universe.
- **Per-category momentum:** for each timestamp, mean 7d close-to-close return across all category members in our universe.
- **Per-symbol features:** for each of N categories, `cat_<name>_momentum_7d` is set to that category's momentum value if the symbol is a member, else NaN. LightGBM handles NaN natively (treated as a separate split).

**Captures:** "memes are hot right now, and this coin is a meme."

**Look-ahead caveat (worth flagging):** CoinGecko categories are not historised cleanly. We'll use **current** category membership applied retrospectively. For categories that existed throughout the period (Memes, DeFi, L1) this is mostly clean — those tokens were always in the category. For newer categories (RWA only became a CG tag in late 2023, AI Tokens around 2024) we accept some retrospective tagging bias and document it. Decision rule: if CoinGecko features alone lift OOS materially but cohort features don't, treat with suspicion (likely tag look-ahead).

**Compute:** ~5 min for fetching, ~10 min for features.

## Decision rules

| Outcome | Action |
|---|---|
| v_new_1.6 ≥ +5% lift over v_new_1.5 (or base) on OOS PR-AUC | Hot-promote v_new_1.6. Ceiling-find with this model. |
| v_new_1.6 0-5% lift (mostly cohort, not categories) | Adopt cohort-only. Drop category features (likely tag look-ahead). |
| v_new_1.6 lift driven by categories alone | **Suspicious** — re-test with CoinGecko membership snapshot dated to t (if feasible) before committing |
| Negative lift | Drop both families. Narrative signal not extractable at this granularity. |

## What's intentionally NOT in v_new_1.6

- **News-event features** (rate cuts, exchange listings, token unlocks): high signal, but requires an event calendar I don't have. Add in v_new_1.7 if v_new_1.6 motivates it.
- **On-chain flow** (DEX volume, holder distribution): more orthogonal signal but new data dependency. Out of scope.
- **Twitter/social mention features**: notoriously noisy, requires sentiment infrastructure. Out.
- **Learned narrative embeddings (Family C from earlier discussion):** wait until cohort-correlation results show whether the simpler emergent approach captures the signal. If yes, embeddings unlikely to add much. If no, may revisit.

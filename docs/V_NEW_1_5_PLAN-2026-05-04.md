# v_new_1.5 — Sequence-feature BGM (no actual LSTM)

**Date:** 2026-05-04
**Status:** Plan locked, executing
**Goal:** Cheap diagnostic. Does adding lagged + rolling v_new_1 scores as features lift OOS PR-AUC and 4-yr return?
**Compute:** VPS only (Biznet, 8 vCPU, 8 → 16 GB RAM upgrade pending).
**DD constraint:** Hard -20% per-year cap stays.

---

## What v_new_1.5 IS

Train the same LightGBM/Platt stack as v_new_1, but augment the 44-feature foundation with **sequence features derived from v_new_1's own scores** at prior timestamps:

- `score_long_t1`  — v_new_1_long score 4h ago (lag 1)
- `score_long_t2`  — score 8h ago (lag 2)
- `score_long_t6`  — score 1 day ago (lag 6)
- `score_long_roll_mean_3d` — 18-bar rolling mean
- `score_long_roll_std_3d`  — 18-bar rolling std
- `score_long_change_1d`    — score_long − score_long_t6
- Same six features for short → 12 sequence features total
- Net feature count: 44 + 12 = 56

Tree boosters capture sequential structure through splits when given lagged features. This is "sequence modeling without LSTM" and runs on CPU in the existing pipeline.

## What v_new_1.5 is NOT

- Not an LSTM. No PyTorch dependency added.
- Not a new label scheme. Same 10%-in-7d big-move labels.
- Not a new universe. Same top-100 USDT perps.
- Not a Phase 4 policy change (yet — that's Track B).

## The leakage gotcha and how we solve it

Naive approach: score every training row with the trained v_new_1 model and use those as lagged features.
**Problem:** the v_new_1 model was trained on those rows. The score it emits is in-sample → using it as a feature leaks the label and v_new_1.5 will overfit.

**Solution: use out-of-fold (OOF) predictions for training rows, raw final-model predictions for cal_fit (which the final model never saw), and calibrated predictions for OOS years.**

| Period | Where it sits in v_new_1 training | Score source for v_new_1.5 |
|---|---|---|
| 2023-04 → 2024-09 (train_fit) | Trained on, in 5 purged folds | **OOF raw probs** captured from each fold's val set |
| 2024-10 → 2025-12 (cal_fit)   | Held out from final fit (fed to calibrator only) | **Raw probs** from final model (non-leaky for cal_fit because final model was fit on train_fit only) |
| 2020 / 2021 / 2022 / 2026 Q1 (OOS) | Never seen by anything | Existing `oos_scored_{direction}_PLATT.parquet` |

Score being raw vs Platt doesn't matter for tree-based meta-learners — Platt is a monotonic transform and trees recover the same splits. We use raw throughout for simplicity.

## Implementation steps

1. **Patch `v_new_1_phase3_train.py`** to capture OOF raw probs during the per-fold loop (lines 514-539) and raw probs on cal_fit, then write `oof_scored_{direction}.parquet` and `cal_scored_{direction}.parquet`. (~30 lines added, no behavior change to existing outputs.)

2. **VPS rerun #1: regenerate v_new_1 with OOF capture.** ~2 hours wall-clock at `LGBM_NUM_THREADS=4`. Outputs the new oof_+cal_ parquets alongside the existing model artifacts.

3. **Build `v_new_1_5_augment_features.py`**: concatenates OOF + cal + OOS scores into a full timeline keyed by (symbol, timestamp), computes the 12 lagged+rolling features per symbol, and merges them into `features_full.parquet` → `features_full_v1_5.parquet`. (~150 lines, runs locally on Mac in <5 min.)

4. **Build `v_new_1_5_phase3_train.py`**: copy of `v_new_1_phase3_train.py` with `FEATURE_NAMES` extended by the 12 sequence features and output paths suffixed `_v1_5`. No other logic changes.

5. **VPS rerun #2: train v_new_1.5.** Another ~2 hours.

6. **Verdict** (in `docs/V_NEW_1_5_VERDICT-{date}.md`): compare median OOS PR-AUC and per-year top-decile precision against v_new_1 baseline (long 0.442, short 0.488).

7. **If verdict ≥ +5% lift on long OR short**: rerun Phase 4 policy opt with v_new_1.5 scores, get new 4-yr return number.

The key signal: if a tree booster with explicit lagged scores can't extract sequence value, an LSTM probably won't either on the same data.

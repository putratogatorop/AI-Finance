# Slim PPO v3.1 — Reduced-Scale RL Trading Agent

**Date:** 2026-04-07
**Status:** Approved
**Supersedes:** v3 design (2026-04-02) for training approach only; gym environment and features unchanged.

## Problem

The v3 RL agent failed to learn because:
1. **178 alts = 534-dim action space** — network can't explore meaningfully
2. **8,559-dim observations** — massive compression through tiny LSTM
3. **Sparse reward** — only at episode end (365 steps of 0.0), PPO has no gradient signal
4. **Population + PPO** — too many moving parts to debug; evolution masks PPO learning failures
5. **Inactivity penalty** created perverse incentive (open positions to avoid penalty, not to profit)

## Solution: Scale Down, Validate, Scale Up

Train a single PPO agent on top 20 alts by volume. Validate it can learn (rewards improve over generations). Then scale up.

## Architecture

### Alt Selection
- Rank alts by total trading volume across all timestamps in the dataset
- Keep top 20 — these have the most liquidity and strongest BTC correlation signal
- Filter at training time (dataset stays the same, `CryptoTradingEnv` receives a `top_n` param)

### Dimensions

| Component | Value |
|-----------|-------|
| Alts traded | 20 |
| Max positions | 20 |
| Alt features | 20 × 28 = 560 |
| BTC/ETH indicators | 9 |
| Portfolio state | 5 |
| **Total obs size** | **574** |
| Action size | 20 × 3 = 60 (score, SL, TP per alt) |

### Network (LSTMPPOAgent)
- No projection layer needed (574 is manageable)
- LSTM: input=574, hidden=128, 2 layers, dropout=0.2
- Actor head: 128 → 128 → 60 (Tanh output)
- Critic head: 128 → 128 → 1
- ~200K parameters
- Initial log_std = -0.5 (std ≈ 0.6, good exploration)

### Reward Function
- **Per step:** `step_return * 100` — scaled so PnL signal (typically ±0.1%) becomes ±0.1 reward
- **Episode end bonus:** existing Sharpe-based formula (0.6×Sharpe + 0.3×NormReturn - 0.1×DDPenalty)
- **No inactivity penalty** — agent learns from PnL naturally
- **No per-step drawdown penalty** — episode-end DD penalty is sufficient

### Training Loop (Pure PPO)
Single agent, no population evolution:

```
for generation in range(N):
    for episode in range(episodes_per_gen):
        rollout = collect_episode(agent, env)
        buffer.add(rollout)
    ppo_update(agent, buffer)   # update after all episodes
    checkpoint(agent)
    log(reward, sharpe, positions, drawdown)
```

Key differences from v3:
- PPO update happens after collecting ALL episodes (not after each episode)
- Larger batch = more stable gradients
- No population, no evolution, no mutation — pure gradient-based learning

### Config Changes

| Param | Old | New |
|-------|-----|-----|
| MAX_POSITIONS | 10 | 20 |
| SCORE_THRESHOLD | 0.3 | 0.15 |
| hidden_size | 256 | 128 |
| episodes_per_gen | 3-10 | 10 |
| PPO epochs | 4 | 10 |
| PPO batch_size | 64 | 256 |
| learning_rate | 3e-4 | 3e-4 |

### Training Script: `train_ppo.py`
- CLI args: `--data`, `--checkpoint`, `--generations`, `--episodes`, `--top-n`, `--cpu`
- Auto-detect CUDA
- Per-generation logging: reward, Sharpe, total return, max drawdown, positions opened, time, ETA
- Checkpoint to Drive every generation
- Resume from checkpoint

### What Stays the Same
- `CryptoTradingEnv` gym logic (SL/TP, fees, funding, 12h windows)
- `Portfolio` tracker
- Feature engineering (28 per-alt + 9 indicator + 5 portfolio)
- `rl_dataset.npz` (no re-export needed)
- Episode structure: 365 windows, 30% drawdown kill

## Success Criteria
- Reward increases over 100 generations (not stuck at 0.0)
- Agent opens and closes positions (not "do nothing" strategy)
- Training completes in <30 min on T4 GPU
- If successful: add population evolution back as v3.2

## Non-Goals
- Population-based training (deferred to v3.2)
- All 178 alts (scale up after validation)
- Live trading integration (Week 3-4)
